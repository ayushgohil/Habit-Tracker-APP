# How Ember is put together

A tour of the code for anyone who wants to change it. Ember is a Flutter app (Android only for now) with a local SQLite database and no server.

## The big picture

```
 Drift database (SQLite)         lib/data/database.dart
        │  streams
        ▼
 Riverpod providers              lib/data/providers.dart
        │  HabitView, HabitHistory, HabitActions
        ▼
 Screens and widgets             lib/ui/…

 Pure logic (no Flutter)         lib/core/…   ← streaks, schedules, goals, timers, dates
 Side effects                    lib/notifications, lib/health, lib/widgets, lib/security
 Android side                    android/app/src/main/kotlin/…
```

Data flows one way. The database emits streams, providers combine them into ready-to-draw views, screens read the providers, and every change goes back through `HabitActions` into the database.

## Folders

| Folder | What lives there |
| --- | --- |
| `lib/core/` | Pure Dart with no Flutter imports, so it is easy to test: `day.dart` (day boundaries), `streak.dart` (streak engine), `goals.dart` (goal history), `timer.dart` (timer state and sessions), `history.dart`, `habit_templates.dart`, `habit_icons.dart`, `link.dart` |
| `lib/data/` | `database.dart` (tables, migrations), `providers.dart` (Riverpod providers and `HabitActions`), `backup.dart`, `csv_import.dart`, `day_start.dart` |
| `lib/theme/` | `ember_theme.dart` (palettes, `EmberColors`) and `theme_controller.dart` (light, dark, follow the phone) |
| `lib/ui/` | One folder per screen: `home`, `add_habit`, `stats`, `timer`, `library`, `notes`, `backup`, `privacy`, `appearance`, plus shared bits in `common` |
| `lib/notifications/` | Reminders and timer notifications |
| `lib/health/` | Health Connect reading (`health_sync.dart`) and writing water (`health_writer.dart`) |
| `lib/widgets/` | Home-screen widgets, launcher shortcuts and widget actions |
| `lib/security/` | The app lock |
| `android/` | The Android project: Kotlin widget providers, resources and the manifest |
| `test/` | Unit and widget tests |
| `tool/` | Maintainer scripts, such as the widget preview generator |

## Database

Drift tables, all in `lib/data/database.dart`:

- `Habits`: name, icon key, colour, task type, schedule, goal, reminders, timer session length, limit mode, link and more
- `Completions`: one row per habit per day, holding an amount (taps, or seconds for timed habits)
- `DayNotes`: the journal note for a day
- `ActiveTimers`: a running or paused timer, stored as banked seconds plus a start time so it survives the app closing
- `HabitGoals`: the goal history, so changing a goal does not rewrite the past

The generated `*.g.dart` files are not committed. Run `dart run build_runner build --delete-conflicting-outputs` after changing a table.

**Changing the schema:** raise `schemaVersion`, add a step to the migration that keeps existing data (usually `m.addColumn`), and test it. Old backups must still restore (see `lib/data/backup.dart`).

## Days, schedules and streaks

- People can choose when their day starts (for example 4 am). Always go through `lib/core/day.dart` (`currentDay`, `currentDayKey`, `dayKey`, `addDays`) rather than comparing raw `DateTime.now()` values.
- A day is stored as a `yyyy-MM-dd` key.
- `lib/core/streak.dart` turns a schedule and the completion history into current and best streaks, completion rate and the "streak at risk" warning.
- "Limit" habits (keep under a time) count every day under the limit as done.

## Timers

`TimerState` in `lib/core/timer.dart` stores banked seconds and when it last started running, so the elapsed time is always recomputed from the clock. `SessionPlan` splits a goal into sessions, and `timerShares` divides a timer that crosses a day change between the days it ran on. Notifications for session ends and the goal are scheduled in `habit_notification_service.dart`.

## Home-screen widgets

Android widgets can only show pictures, so the cards are drawn in Dart:

1. `card_data.dart` builds the numbers for each habit and card kind.
2. `card_painter.dart` draws them to 400×400 PNGs.
3. `widget_cards.dart` writes the PNGs to the app's folder and tells Android to refresh the widgets.
4. The Kotlin providers in `android/app/src/main/kotlin/com/nextlyr/ember/` (`EmberCardWidgets.kt`, `EmberWidgetProvider.kt`) pick the right image and tint it for the chosen style.
5. Taps come back into Dart through `widget_actions.dart`.

The widget picker previews are generated by `tool/make_widget_previews.py` (`python3 tool/make_widget_previews.py`, needs Pillow).

## Automation and shortcuts

`EmberAutomation.kt` receives broadcasts named `com.nextlyr.ember.action.LOG`, `COMPLETE`, `START` and `STOP` (with a `habit` text extra) and the Quick Settings tile. They end up in `widget_actions.dart` as well, so a habit changes the same way wherever the tap came from.

## Theme and icons

`EmberPalette` describes one colour theme; `emberPalettes` lists them and `activePaletteProvider` picks the current one. Icons are stored as string keys (`habit_icons.dart`). Never rename a key: it is saved in the database and in backups.

## Where do I change…?

| I want to… | Start in |
| --- | --- |
| Change how a streak is counted | `lib/core/streak.dart` and `test/streak_test.dart` |
| Add a habit icon | `lib/core/habit_icons.dart` (add a new key; do not rename) |
| Add a colour theme | `lib/theme/ember_theme.dart` |
| Add a field to a habit | `lib/data/database.dart` (table, migration), `providers.dart`, `add_habit_screen.dart`, `backup.dart` |
| Change a chart | `lib/ui/stats/` |
| Change a widget | `lib/widgets/` and the Kotlin files in `android/` |
| Add a habit template | `lib/core/habit_templates.dart` |
| Change reminders | `lib/notifications/habit_notification_service.dart` |

## Tests

`flutter test` runs everything in `test/`. Widget tests drive the real app against an in-memory database; look at `test/home_flow_test.dart` for the pattern and its `settle` helper. See [CONTRIBUTING.md](../CONTRIBUTING.md) for the habits that keep them reliable.
